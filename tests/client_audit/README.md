# WFX client audit

Adversarial correctness and security testing for the two protocol clients WFX
ships: `WFX::HttpEndpoint` (`include/wfx/endpoint/http.hpp`) and
`WFX::SmtpEndpoint` (`include/wfx/endpoint/smtp.hpp`).

Where `tests/base_audit` tortures WFX as an inbound **server**, this suite
tortures it as an outbound **client**. Each protocol gets a fully hostile mock,
and every vector is fired *through* WFX at it.

The **HTTP/1.1** half attacks the response parser and the request serializer. The
client must never crash, never hang past its timeout, never mis-frame one
response into the next, never smuggle a request, never leak one request's data
into another, and never let a malicious upstream poison a pooled keep-alive
connection.

The **SMTP** half drives full `EHLO`, `STARTTLS`, re-`EHLO`, `AUTH`, `MAIL`,
`RCPT` and `DATA` transactions against one hostile listener per persona, covering
the handshake state machine, both AUTH mechanisms, STARTTLS injection and
downgrade, certificate rejection, connect and mid-transaction hangs, abrupt drops
at every stage, and CR/LF/NUL injection through every caller-supplied field.

The raw `WFX::Endpoint<>` primitive both clients are built on is audited
separately, in `tests/endpoint_audit`.

---

## Scope: this suite vs `tests/tls_audit`

Both suites touch TLS, so the boundary is worth stating plainly.

**`tls_audit` owns the certificate and trust surface for endpoints that are TLS
from the first byte** (`EpTlsRequire`): untrusted, hostname-mismatched and
expired certs refused, version downgrade refused, sessions resumed. It needs
`mkcert` and a CA-trust step.

**This suite's HTTP half stays plaintext**, so it needs no certificates: every
vector here is about framing, smuggling and lifecycle rather than trust.

**This suite's SMTP half owns its own TLS surface**, including certificate
rejection (`smtp_certs`). STARTTLS does not fit `tls_audit`'s model at all: it is
an in-band upgrade of an already-open plaintext connection, never TLS from the
first byte. `smtp_upstream.py` therefore gets its own throwaway CA and cert set,
generated by `ensure_smtp_certs()` in `client_audit.py`.

## Architecture

```
audit (client_audit.py) --HTTP--> WFX app /call, /inject      --HTTP--> http_upstream.py :8091
                        --HTTP--> WFX app /smtp/*             --SMTP--> smtp_upstream.py, one port per persona
                        +-------- stages raw bytes, reads counters ---------------------+
```

The audit never speaks to an upstream's data port. It drives WFX, WFX drives the
mock, and each mock's counters come back over its own control channel, so a claim
like "the client bailed at the TLS layer" is the mock's own evidence rather than
an inference from a failed call.

**`app/`** is a WFX project scaffolded with `wfx new`, all in `src/main.cpp`.
`/call` turns one inbound request into one outbound `HttpEndpoint` call, chosen
entirely by `X-*` headers, and reflects the result as JSON (`{"ep", "status",
"bodylen", "body", "hdr"}`, where `ep` is the `EndpointStatus` int and `0` is
success). `/inject` carries a hostile path or header in its POST **body**, which
is the only way to get a real CR/LF/NUL past WFX's own inbound parser.

Nine endpoint instances give each group of vectors the knobs it needs. `default`
is the everyday client. `small` has tiny header, body and header-count caps.
`fast` runs a 5s budget, the engine's floor, over two slots, which is what makes
pool exhaustion reachable. `coalesce` sets a dedup key, and `reuse` has a single
slot, so cross-request bleed is observable. Four more are lifecycle probes:
`dead` points at a port with nothing listening, `unreach` at an unrouteable
TEST-NET address, `idle` runs a 5s idle timeout, and `prewarm` opens three
connections at boot.

`/smtp/send` drives a transaction one command at a time, so a failure names the
stage it happened on: `reserve`, `mail`, `rcpt`, `data_start`, `data_body` or
`done`. `/smtp/send-mail` drives the same transaction through `SendMail`, which
is what proves a `WFX::Coro` can be co_awaited from another coroutine end to end
rather than merely compile. `/smtp/inject` splices a hostile payload into
whichever caller-supplied field `X-Field` names, the role `/inject` plays for
HTTP.

**`http_upstream.py`** is a thin raw-socket **byte oracle** on port 8091. Its key
trick is **staging**: `POST /ctl/stage` an arbitrary raw response, then have WFX
fetch `/raw/<id>`, optionally dripped or split mid-write (`X-Mode: drip` or
`split`) so the incremental parser has to reassemble across `recv()` boundaries.
`/reflectraw` hands back the exact request bytes WFX emitted, for byte-for-byte
serializer checks. The vectors live in the audit, not in the mock.

**`smtp_upstream.py`** runs one fixed listener per persona (see `SMTP_PERSONAS`
in `client_audit.py`, each wired to its own `SmtpEndpoint` in
`app/src/main.cpp`), each running the real handshake state machine with exactly
one thing flipped: refuse STARTTLS, inject plaintext, present a bad cert, fail
AUTH, hang, or drop at a named stage. A control listener on port 8199 answers
`STATS <persona>` and `RESET <persona>` with per-persona counters.

## Run

```bash
cd tests/client_audit

python3 client_audit.py                      # everything
python3 client_audit.py --phase http_desync  # one phase
python3 client_audit.py --list-phases        # what phases exist
python3 client_audit.py --wfx-logs all       # stream every WFX log line
python3 client_audit.py --ci                 # no colors, GitHub Actions groups
```

The runner generates the SMTP certs into `certs/` (gitignored), points
`outbound_ca_path` at the throwaway CA it just made, launches both mocks, boots
the app with `wfx run app --port 8080 --detach`, drives every vector, stops
everything, and prints a per-phase report.

> That CA rewrite edits `app/config/wfx.local.toml` in place, so a run leaves the
> file holding an absolute path from *this* machine. Don't commit that line:
> checked in, it points every other checkout (and CI) at a CA that isn't there,
> and WFX refuses to build its outbound TLS context at all. Leave it as `""`.

### Requirements

- `wfx` and `openssl` on `PATH` (or `--wfx /path/to/wfx`)
- Python 3.8+, standard library only
- Linux

### Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--host` | `127.0.0.1` | Host for WFX and both mocks |
| `--port` | `8080` | WFX inbound port |
| `--http-port` | `8091` | HTTP mock port, must match `UPSTREAM` in `app/src/main.cpp` |
| `--wfx` | `wfx` | Path to the wfx binary |
| `--app-dir` | `app` | App directory passed to `wfx run` |
| `--ready-timeout` | `30` | Seconds to wait for `/health` |
| `--phase` | `all` | Run a single phase |
| `--list-phases` | n/a | Print phases and exit |
| `--wfx-logs` | `important` | Stream WFX logs live: `off`, `crash`, `important`, `all` |
| `--ci` | off | No colors, GitHub Actions `::group::` and `::error::` commands |

> The HTTP mock's port is **compile-time baked** into the app (`#define UPSTREAM
> "127.0.0.1:8091"`), and so is every SMTP persona's port. Passing a different
> `--http-port` without also editing that line and rebuilding leaves WFX unable to
> reach the mock. The runner warns about the mismatch at startup, then its
> preflight call fails and names `UPSTREAM` as the reason, so the run reports that
> once instead of every phase failing for it separately. The SMTP ports get no
> flag at all, since a flag that cannot change anything is worse than none.

### Exit codes

| Code | Meaning |
|------|---------|
| `0` | All vectors passed |
| `1` | Correctness failure, or the WFX worker died during the run |
| `2` | **Security** finding, listed under Phases below |
| `3` | WFX never answered `/health`, so nothing was exercised |

## Phases

Run `python3 client_audit.py --list-phases` to get this list straight from the
script, and re-check it against the table whenever a phase is added or removed.

### HTTP

| Phase | What it proves |
|-------|----------------|
| **http_framing** | The whole *legal* response matrix is accepted: Content-Length, chunked, close-delimited, HTTP/1.0, HEAD, 1xx interleaves, 204 and 304 |
| **http_statusline** | Malformed status lines are rejected rather than crashing the parser, and the ones that only *look* malformed are still accepted |
| **http_headers** | Header framing and smuggling: obs-fold, duplicate `Content-Length`, `CL` and `TE` together, and every `Transfer-Encoding` spelling that is and is not chunked |
| **http_chunked** | Chunk sizes and framing at the edges: overflow, malformed terminators, extensions, trailers, and 200 one-byte chunks reassembling exactly |
| **http_eof** | Truncation at every parser phase, including a byte-at-a-time drip into EOF, and the cases where EOF legitimately *is* the end of the message |
| **http_desync** | Keep-alive poisoning and response smuggling: after a hostile response, a burst on the same pool must stay pristine, and the smuggled bytes must never be delivered |
| **http_serialize** | The request side: engine-owned headers deduplicated, `Content-Length` correct at every size, buffer-grow retries on a 6KB header and an 8KB body, CR/LF/NUL refused in paths and headers, and the emitted head checked byte for byte |
| **http_limits** | `EpSmall`'s header, body and header-count caps at the exact boundary, at cap and one over, in each of the three body framings |
| **http_resource** | Timeouts, pool exhaustion, coalescing dedup, clone integrity for every waiter, error fan-out, and two distinct keys in flight without cross-delivery |
| **http_fragmentation** | Incremental parsing under `recv()` splitting: a one-byte drip, and one split at *every* byte offset of a fixed-length response |
| **http_methods** | Every verb serializes correctly and round-trips, bodyless verbs stay bodyless, and HEAD stays bodyless even when the upstream advertises a length |
| **http_security** | Cross-request bleed on a reused connection, trailer and 1xx header leaks, keep-alive poisoning variants, the full injection corpus, and DoS caps |
| **http_lifecycle** | Connect refused, host unreachable, transparent reconnect, keep-alive reuse, idle recycling, and eager prewarm at boot |
| **http_metrics** | `/metrics` counters match what was driven exactly: requests, completions, each status class, latency samples, connect failures, timeouts, pool exhaustion, parse errors, coalesce hits, and the in-use gauge back to zero |

### SMTP

| Phase | What it proves |
|-------|----------------|
| **smtp_handshake** | The happy path end to end, through both the step-by-step API and `SendMail`, with RFC 5321 dot-stuffing round-tripping byte for byte |
| **smtp_auth** | `AUTH PLAIN` and `AUTH LOGIN` selection, wrong credentials refused, and a server offering neither mechanism refused rather than worked around |
| **smtp_starttls** | STARTTLS enforcement, the CVE-2011-0411 / CVE-2026-41319 plaintext-injection persona, a spliced continuation code, and a banner that is not SMTP at all |
| **smtp_certs** | STARTTLS certificate rejection. Untrusted, hostname-mismatched and expired certs are all refused, and each refusal is proven twice over: the outbound call fails, and the mock recorded a *failed* TLS handshake rather than a completed one |
| **smtp_resource** | Handshake and mid-transaction hangs resolve through the line caps or the connect/request budget, never block forever |
| **smtp_drops** | An abrupt disconnect at every handshake stage is refused cleanly, without hanging |
| **smtp_inject** | CR/LF/NUL injection through every caller-supplied field, and through `heloName`, screened before a byte reaches the wire |

A check that fails and is marked **security** forces exit code `2`. In this suite
those are: a keep-alive connection poisoned or desynced by a hostile response, a
smuggled request or response body delivered as real, a CR/LF/NUL reaching the
wire through a path, a header or an SMTP field, one request's headers or body
surfacing in another's, coalesced waiters receiving the wrong key's response, and
an SMTP session that continues in plaintext or trusts pre-TLS bytes. Read the
assertions themselves in `client_audit.py` (search for `def phase_<name>`) for
the exact vectors. These tables map to the code, they do not replace reading it.

Phases can trip **security** findings, which force exit code `2`: a tripped
desync, smuggle, injection, bleed, leak or accepted downgrade means a hostile
upstream defeated the client. See the phase's own assertions in `client_audit.py`
(search for `def phase_<name>`) for the exact vectors; this table is a map to the
code, not a substitute for reading it.
